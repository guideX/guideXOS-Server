ADD IBM S390X ARCHITECTURE SUPPORT TO guideXOS SERVER (C++)

You are working inside the guideXOS Server codebase written in modern C++.

GOAL:
Add full, clean, and extensible support for the IBM s390x (IBM Z mainframe) architecture across the system, without breaking any existing architectures (amd64, x86, arm, arm64, riscv, powerpc, mips64, loongarch, sparc64, sparc8).

This is NOT a full emulator implementation. It is a full architectural integration: detection, abstraction, endian safety, filesystem correctness, syscall compatibility, and test coverage.

────────────────────────────────────────────────────────────

────────────────────────────────────────────────────────────

3. ENDIANNESS + SERIALIZATION SAFETY (CRITICAL)
────────────────────────────────────────────────────────────

s390x is BIG-ENDIAN. This is critical.

Update all serialization and binary I/O systems:

- Replace any raw struct disk writes with explicit serialization
- Ensure all filesystem structures are endian-safe:
  - inode
  - directory entries
  - superblock
  - journal/log entries (if present)

Implement or extend:
- to_big_endian()
- to_little_endian()
- read/write primitives for:
  - uint16_t
  - uint32_t
  - uint64_t

Rules:
- On-disk format must be architecture-independent
- Host memory layout must never directly define disk format
- Avoid undefined struct padding assumptions

Add compile-time or runtime assertions verifying:
- correct endian mode for s390x builds

────────────────────────────────────────────────────────────

Ensure filesystem layer is fully portable:

- All FS metadata must be serialized explicitly
- Remove any dependency on:
  - struct packing assumptions
  - native pointer sizes in disk structures
- Ensure cross-arch compatibility:
  x86 ↔ arm64 ↔ riscv ↔ s390x
