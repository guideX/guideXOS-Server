# guideXOS Server v0.3 Integration Readiness Audit

Date: 2026-10-04  
Classification: **Integration plan; no feature branches merged**

## Executive decision

The v0.3 candidate set is not ready to assemble as a release candidate today. The principal intended v0.3 item, the Sci-Fi theme, has a branch-level freeze recommendation of “ready for v0.3 integration,” but its branch is based on an older main and changes core files that have since received App Model Phase 22 work. It needs a current-main integration pass and qualification before it is safe to merge. Other attractive candidates are either independent feature work that should stay outside v0.3, or have explicit hardware/GUI qualification gaps.

**Recommended first feature:** reconcile and integrate the frozen Sci-Fi theme onto current `main`, preserving the current Classic default and Phase 22 Notepad/dialog isolation. Do this as a bounded theme integration task with conflict resolution and its existing Classic/Sci-Fi validation matrix. Do not take the entire old branch as a blind merge.

**Current true release blockers:** no v0.3 integration candidate has been qualified against current `main`; no assembled v0.3 image has passed the required post-integration regression matrix; and no v0.3 release-candidate evidence/package exists. The Sci-Fi reconciliation is therefore the first feature gate. DM31's incomplete GPT GUI transaction is a blocker only if the DM30/31 Disk Manager improvements are brought into v0.3. No evidence makes .NET, Developer Studio, AArch64, Navigator JavaScript, or modern xHCI a v0.3 requirement.

## 7. True blockers, risks, and polish

### True v0.3 release blockers today

1. **The frozen Sci-Fi candidate has not been reconciled and qualified against current `main`.** The current v0.3 visual release cannot claim the Sci-Fi deliverable until its current-source integration passes.
2. **No integrated v0.3 release candidate exists.** No post-integration AMD64 image/package, full regression result, or release-candidate evidence is recorded.
3. **The audit cannot verify remote freshness or push availability.** SSH fetch/push requires restored access by the user's normal environment; no credential or remote changes are warranted. This blocks a confirmed upstream handoff, not local audit completion.

### Conditional blockers if expanded into v0.3

- Disk Manager GPT repair/destructive flows: finish the DM31 graphical Cancel/Confirm/result/cold-restart qualification and run it on current integrated source before release.
- Any claim of new physical Intel I219 networking: obtain successful physical TX evidence on the target system. Not a blocker for existing supported legacy E1000/QEMU networking.
- Modern USB HID input: complete enumeration/HID and physical xHCI validation. Not required to release current supported input paths.

### Risks (document and manage; not independently release-stopping)

- The candidate branches have stale local base refs and some dirty worktrees; their ahead counts are not current remote divergence counts.
- The SSH remote is currently inaccessible from this environment.
- Theme test harness limitations include incomplete direct per-utility QEMU screenshot retention; the theme report classifies this as a bounded evidence limitation, not a visual blocker.
- Settings S9 reports missing full native visual acceptance. Settings is already present; this is not a blocker unless the release specifically requires that acceptance.
- App Model Phase 22 retains documented limitations: exact live buffer-byte extraction/native visual acceptance unavailable and same-file concurrent saves are last-writer-wins. Preserve those claims and do not convert them into a v0.3 blocker absent a product requirement.

### Polish / explicitly deferred

Blur/glass/transparency/animation/shadow-engine rewrite, major visual redesign, universal icon replacement, font-engine replacement, Navigator full ECMAScript/DOM compatibility, general user-profile/security implementation, AArch64 broad hardware support, managed app bulk integration, and I219 root-cause work are not required to call the scoped v0.3 theme release complete.

## 9. Post-integration regression and RC gate

After the theme integration, the integrator must run and record:

1. Clean hosted and AMD64 builds from the final candidate commit; include build identity and toolchain.
2. Theme focused test and authoritative theme smoke, including Classic default/missing/invalid fallback, Sci-Fi opt-in and persistence, and unchanged geometry/hit regions.
3. Startup App Model regression and the Phase 20/22 lifecycle and Notepad concurrency regressions; explicitly cover independent buffers/dialog results, open/save/save-as/cancel/close, multiple instances, and overlap cycles.
4. Settings center/network/storage model and service contracts; Navigator baseline; File Explorer launch/navigation and utility launch/close regressions.
5. QEMU AMD64 Classic and Sci-Fi boots using disposable staged ESPs. Preserve serial/build identity and representative guest captures. Verify all required themes and launch paths on the exact final candidate bits.
6. `git diff --check`, review generated artifacts, check only intended files are changed, inspect commit ancestry/conflict resolution, and rerun any test affected by a resolved conflict.

**RC gate:** all mandatory rows above pass on one identified commit; no uncommitted files; all test results and known gaps are recorded; Classic stays the default; Sci-Fi works as the opt-in theme; no unresolved conflict or release blocker; release notes claim only exercised platforms and capabilities. A failure in a v0.3-scoped theme/App Model launch path blocks RC until fixed and rerun. Disk Manager, I219, xHCI, .NET, Developer Studio, AArch64, and Settings visual expansion do not enter the gate unless added to the declared v0.3 scope.

## 10. Honest v0.3 claims

After theme integration and the RC gate, v0.3 can claim a scoped, opt-in Sci-Fi presentation on the qualified hosted/AMD64 paths, with Classic remaining the compatibility default; the existing App Model with Phase 22's documented hosted concurrent-Notepad behavior and limitations; and existing, already integrated applications and services whose current regressions pass.

v0.3 cannot claim that the Sci-Fi theme has broad physical-device certification from QEMU evidence; full native visual acceptance where captures are unavailable; universal feature parity across every app surface; general ECMAScript/browser compatibility; complete USB HID/xHCI input; physical I219 networking; broad AArch64/tablet support; Settings 1.0 full visual acceptance; or the v1.1 managed runtime/Developer Studio work as integrated current-main functionality.
