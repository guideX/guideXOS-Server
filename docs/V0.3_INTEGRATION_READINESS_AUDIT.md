## Wallpaper root cause and release significance

Classification: **ISOLATED ACCEPTANCE-FIXTURE LIMITATION**.

The normal runtime image is included in the ESP as `ramdisk.img` and handed to the kernel at boot. The kernel attaches that memory read-only and mounts it at `/system`; built-in wallpaper paths use `/system/wall`. If the isolated fixture omits the RAM-disk file at boot, the kernel has no pack to attach, matching the prior “not mounted” report. Adding a PNG to host-backed ESP storage after launch does not update the RAM disk already loaded by the bootloader. The prior acceptance fixture itself was not inspected, so the precise omission is supported by the supplied report and matching source behavior, not a fresh fixture image inspection.

Working wallpapers/images are intended v0.3 desktop content. The dedicated workspace's build and local ESP staging contain the image pack, so the earlier observation does not establish a release-packaging defect or Sci-Fi defect. Sci-Fi release readiness still requires visually checking a wallpaper on the selected theme.
