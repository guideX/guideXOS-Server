## Implemented observation

Build AMD64 with `BSP_APIC_DIAGNOSTIC=1` to enable the three `[CPU6]` serial lines. The gate works independently of `CPU_INVENTORY_DIAGNOSTIC`. Either diagnostic obtains the processor inventory and interrupt topology through the existing checked BootInfo accessors. The ordinary build excludes the CPU6 object. Switching the CPU6 flag in a reused AMD64 object directory rebuilds the boot hook and relinks. The qualification builds used clean directories for all flags. [Build gate](../kernel/Makefile) · [BSP boot hook](../kernel/arch/amd64/per_cpu.cpp) · [BootInfo validation](../guideXOSBootLoader/bootinfo_acpi.h)

1. The report prints CPUID MSR, APIC, and x2APIC bits as set, clear, or unreported. It samples `IA32_APIC_BASE` (`0x1B`) once after CPUID enumerates both MSRs and APIC. An explicit clear is reported as `unsupported-by-cpuid`. Global disable can itself clear the CPUID APIC bit on some CPUs, so this case leaves the hardware mode unknown. Missing CPUID or an unavailable reader also leaves the hardware mode unknown.
2. The raw MSR supplies BSP bit 8, global enable bit 11, and the x2APIC mode bit 10 when CPUID advertises that feature. The report preserves all raw bits. A set bit 10 with global enable clear, a set bit 10 without its CPUID prerequisite, or set fixed reserved bits gives an invalid mode encoding. A valid clear global-enable bit gives disabled. A valid set global-enable bit selects xAPIC or x2APIC using bit 10. This observes global enable. The software-enable bit in the Spurious Interrupt Vector Register remains uninspected.
3. Bits 51:12 supply the reported page address. The validator checks the fixed high reserved bits, rejects a zero candidate, and checks the address against a reported physical width in the supported 32–52 range. An absent or nonsensical width leaves the candidate unverified. The width bound is an address sanity check. Future use as an MMIO address requires any narrower model-specific APIC limit, including applicable Intel TME KeyID constraints, and independent mapping validation. CPU5's resolved MADT candidate applies the type-5 override policy. The report shows the header and effective address and compares valid candidates numerically, including in x2APIC mode where the base is not an active MMIO aperture.
4. The executing CPU's initial APIC ID is compared with CPU3's logical BSP descriptor. The report identifies 8-bit versus full-width CPUID identities, rejects width-insufficient comparisons, and shows whether CPU3 matched a firmware record. A match in the BSP-only fallback compares against a descriptor derived from that same CPUID observation. Even with a firmware match, this identifies the initial APIC ID. Some xAPIC implementations allow the live ID register to be programmed. The independent hardware BSP bit is emitted alongside the MSR state.

An observed MSR, disabled controller, unenumerated feature, unavailable observation, and inaccessible xAPIC aperture have separate output. x2APIC ID and version MSRs remain deferred. This path invokes no APIC writes, APIC EOI, IPI, mappings, or secondary startup. ## PIC/PIT and CPL3 compatibility

The 8259 master and slave are initialized at vectors `0x20–0x2F`. The IRQ registration code installs a handler and unmasks the source, opening master IRQ2 for slave lines. The IRQ stub supplies a legacy IRQ number and dispatch sends EOI after invoking the handler, to the slave first for IRQ8–15 and to the master for every IRQ. The framebuffer path and fallback console path initialize the PIC and register PIT channel 0 on IRQ0 at 100 Hz. The desktop registers PS/2 keyboard IRQ1 and pointer IRQ12. The optional COM2 bridge owns IRQ3 when configured. The PIT tick continues to drive desktop time and idle wakeups. [PIC and dispatch](../kernel/core/interrupts.cpp) · [PIT](../kernel/core/pit.cpp) · [Startup registrations](../kernel/core/main.cpp) · [COM2](../kernel/core/system_service_bridge.cpp)

The protected-task pilot retains the existing GDT/TSS selectors, owned entry stack through TSS RSP0, and the DPL3 `0x80` exit gate. The AMD64 stubs and assembly retain interrupt-stack, Microsoft x64 alignment and shadow-space, private CR3, fault-recovery, and off-stack cleanup behavior. Stock PacMan remains a synchronous CPL0 Native ELF launch. CPU6 runs before task entry or any change to the executing CPU's interrupt ownership. ## Outstanding qualification

- A CPU or VMM that advertises MSR/APIC support but faults on `RDMSR 0x1B` can fail the opt-in boot. Mock read failure covers reporting when a reader can return failure. It does not establish a native `#GP` or virtualization-exception recovery path. The stock build does not execute the diagnostic.
- CPU6 supplies no live SVR, LINT, version, ISR, redirection capacity, or interrupt-delivery-mode evidence. Physical-platform coverage and a live x2APIC or disabled-state sample require independently qualified lanes. Numeric agreement with the MADT supplies no mapping or routing authority.
- The separate ACPI-disabled CPU4 control stopped in firmware before guideXOS loader entry. It remains open. The CPU6 hosted tests model an absent or unusable handoff. [CPU4 guest qualification](CPU_IMPROVEMENTS_CPU4.md#guest-qualification)

## Proposed CPU7 activation contract

Review the proposed ownership transition independently before implementation. Keep the first activation pilot opt-in and BSP-only. Qualify the following prerequisites before routing any interrupt.

1. **Verify the initial state and candidate route plan.** Require a supported BSP mode, validated mappings and cache aliases where required, and known LAPIC software enable, LINT, LVT and priority state. Verify live I/O APIC IDs and redirection counts under a separately reviewed lock or single-owner selector protocol. Check GSI arithmetic, coverage, overlap, polarity, trigger, and destination width against the MADT. GSIs 2, 1 and 12 are the current guest's candidates for PIT, keyboard and pointer. Include IRQ3 where COM2 is enabled. Require a reachable BSP destination for every source. Resolve NMI sources and LINT ownership before touching controller state. [ACPI MADT](https://uefi.org/specs/ACPI/6.6/05_ACPI_Software_Programming_Model.html#multiple-apic-description-table-madt) · [CPU5 topology](CPU_IMPROVEMENTS_CPU5.md)
2. **Publish vector and acknowledgment ownership.** Separate IRQ, GSI, and IDT vector namespaces. Keep exceptions `0x00–0x1F`, the legacy PIC range during transition, and the CPL3 gate `0x80` out of allocation. Install distinct local error and spurious vectors and reserve space for the timer and future IPIs. Each active source has one route and an entry that knows its controller acknowledgment contract. Handle and deassert level-triggered sources before LAPIC EOI. Verify I/O APIC remote-IRR clearing with the selected broadcast or explicitly supported directed EOI policy. Preserve the PIC cascade's EOI semantics and handle IRQ7/15 spurious cases using the PIC ISR. A LAPIC spurious interrupt and an NMI do not receive a LAPIC EOI. During any explicitly qualified virtual-wire phase, ExtINT retains PIC acknowledgment semantics. [Intel SDM Vol. 3A, §13](https://cdrdv2-public.intel.com/874240/325462-090-sdm-vol-1-2abcd-3abcd-4.pdf)
3. **Make ownership a bounded transition.** Snapshot the relevant PIC/LAPIC/I/O APIC state. Install the IDT entries and establish the error, spurious, NMI and exception paths first. Mask new routes and unused LVT entries while validating their programming and readback. Quiesce affected sources or explicitly handle pending legacy edges and in-service levels. Under BSP interrupt exclusion, mask the 8259 for I/O APIC ownership on PC-AT-compatible systems and retire any legacy LINT ExtINT route in the verified platform order. Publish the new dispatch owner before unmasking one verified source at a time. Restore IF only when the active route and handler agree. Treat NMI separately from IF. For each transition stage specify supported register ordering, failure detection, and which state is reversible. On failure mask new delivery first and restore the saved PIC/virtual-wire path before re-enabling interrupts if that rollback is qualified. Otherwise contain the failure in the opt-in boot and recover through a separate stock boot. [ACPI MADT flags](https://uefi.org/specs/ACPI/6.6/05_ACPI_Software_Programming_Model.html#multiple-apic-description-table-madt) · [Intel SDM Vol. 3A, §§13.4 and 13.12](https://cdrdv2-public.intel.com/874240/325462-090-sdm-vol-1-2abcd-3abcd-4.pdf)
4. **Keep timekeeping independent of scheduling.** First preserve the 100 Hz PIT heartbeat and idle wakeup through the verified route, with one owner of the tick counter and an independent, bounded way to detect missing ticks. Evaluate a LAPIC timer or TSC deadline separately after selecting a reference clock and validating rate, missed events, idle wakeups, masking and rollback. Test keyboard, pointer, PacMan and CPL3 during the timer cutover. Scheduling and timer preemption require their own milestone. [PIT contract](../kernel/core/pit.cpp)
5. **Qualify CPU-local entry state before wider delivery.** Give each executing CPU a kernel stack, TSS and RSP0, private IST storage for the selected exception/NMI policy, and per-CPU interrupt nesting and recovery state. Load GDTR, IDTR and TR per CPU. Preserve the existing CPL3 frame, CR3 switch, kernel-stack mapping and return/cleanup ordering. Fix nesting hazards in the shared exception stack and recovery globals before AP delivery. Future SMP scheduling also requires CPU-local current-task and extended-state ownership, synchronized interrupt registration and command queues, and a bounded IPI/TLB acknowledgment protocol. Qualify AP startup and online publication separately. [CPU3 ownership audit](CPU_IMPROVEMENTS_CPU3.md#single-cpu-assumptions) · [AMD64 entry stubs](../kernel/core/interrupts.cpp)
