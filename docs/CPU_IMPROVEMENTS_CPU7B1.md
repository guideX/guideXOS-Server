## Admission and mapping contract

Build AMD64 with `BSP_XAPIC_ADMISSION_DIAGNOSTIC=1` to enable the diagnostic independently of CPU inventory and CPU6. CPU7B1 runs once after logical CPU 0 is marked online. The stock build omits its object and call site. CPU7B1 reuses CPU6's pure decoder via a value-copy callback. Its boot hook supplies empty MSR and mapping evidence and consumes the checksum-validated ACPI data already available to CPU3/CPU5. [Build gate](../kernel/Makefile) · [Boot hook](../kernel/arch/amd64/per_cpu.cpp) · [Evaluator](../kernel/arch/amd64/bsp_xapic_admission.cpp)

1. Require CPUID long mode, MSR and APIC support, and a valid xAPIC-width identity from the enabled firmware-mapped BSP of a single-online-CPU roster. Require an untruncated, structurally usable MADT topology. Resolve the header or unique valid address override and reject any declared I/O APIC in that page, including a misaligned I/O APIC address within it. When independently obtained, the current-boot base MSR must encode valid, globally enabled xAPIC with the hardware BSP bit and agree with the resolved MADT page. The initial APIC ID correlation and numeric base agreement supply admission evidence. Live software enable and controller identity remain unobserved.
2. Admit exactly one nonzero, aligned 4 KiB physical aperture within a reported width of 32 to 52 bits. Use subtraction before adding the span. The proposed virtual page must be aligned, canonical in the four-level kernel half and have a representable end. The evaluator requires a producer to attest to exclusive platform MMIO ownership, RAM and reserved-range exclusions, and a vacant reserved virtual slot with no physical aliases. The alias audit must cover identity/device windows, large pages and applicable roots. A positive firmware address alone cannot attest to these conditions. The producer must account for platform-specific physical address restrictions, including address bits used for encryption or KeyIDs.
3. Require a validated four-level tree rooted at the same normalized physical CR3 address as the active root. The detached plan must propose a present supervisor-only, read-only, NX, non-global 4 KiB leaf encoding the admitted physical page. It requires CPUID NX, observed EFER.NXE, and observed CR0.WP. All ancestors and other mappings remain part of the root and alias audit. The leaf's PAT/PWT/PCD bits select the byte in the observed PAT. The narrow effective UC profile accepts strong UC in that slot and a verified strong UC MTRR result for the full page. UC- and all other combinations are outside this qualified subset. The MTRR producer must resolve enablement and fixed, variable and default ranges, reject unreadable or conflicting inputs, and establish the platform's normal cache-control conditions.
4. Charge all reachable tables, including self-maps, to the 1,024-page limit. A single 4 KiB leaf can require up to three new table frames. Admission uses the remaining budget and the available kernel-owned frame count. The plan is evidence bound to one BSP, root, physical page and boot. The repository has no native producer for the full evidence and no publication API. `plan-eligible` describes the validated synthetic plan.

The reporter emits distinct status names for unsupported CPU/mode, unavailable or invalid firmware, invalid address, missing safe MSR evidence, firmware/MSR disagreement, ownership, alias, root, permissions, cache and capacity. Every boot report records `mapping=not-installed controller-access=not-attempted`. A future successful installer must separately report that it published and verified the mapping before any register access.

### Lifetime and transaction requirements

CPU7B1 holds no mapping handle, frames or TLB state. Repeated evaluation is read-only, and repeated boot initialization leaves the original roster and report intact. For the first future probe, scope the mapping to the active kernel root before any protected-task root is created. Stage all allocations and table writes off-tree, validate the prepared path and frame ownership, and publish under exclusive BSP ownership. Failure while staging must release every staged frame and leave the active tree and counters intact. After publication and teardown, invalidate the local translation before releasing or reusing frames. Recheck the leaf and ancestor ownership before unlinking. Keep the probe mapping out of the task-private user slot.

If a later milestone needs the mapping while task CR3 is active, publish a supervisor-only kernel entry before task roots copy it, or provide explicit root synchronization and invalidation before allowing access. Keep the shared subtree kernel-owned for the full lifetime of every root that references it. Unpublish only after removing all references and invalidating affected translations. A task destroy operation must never reclaim those shared frames.

## Cross-branch compatibility

CPU7B1 changes no BootInfo structures, flags, checksums or loader mappings. The CPU branch still uses base v3 with CPU4's arena fields and CPU2/CPU5's checked extension tails. The local Modern Input ref `26f54d40` uses v4 and adds input handoff fields. Disk Manager `723046ff` also uses v3 but changes that layout and its validation. Security Settings `cc8d9d0d` uses v2 and changes the kernel entry path. .NET Support `97dc7b0d` uses v1 and makes larger boot and kernel changes. None has the CPU branch's `bootinfo_acpi.h`. A matching version number alone is insufficient for mixing loaders and kernels. Reconcile layouts, valid flags, handoff sizes and consumers together before any integration. No cross-branch merge was performed.

## Outstanding blockers and CPU7B2 scope

Schedule an intermediate AMD64 entry and fault-containment milestone before CPU7B2. Qualify nesting-safe exception, NMI and double-fault paths, correct frame classification and DF handling, and preserve the current PIC/PIT and CPL3 results. Add exact-site fault recovery for a current-boot BSP MSR read after safe IDT installation. Include a controlled success, a contained failure and proof that unrelated exceptions still follow their normal handler. Establish the independent ownership, alias, cache, permissions and table-budget evidence with a transactional single-page publisher and teardown, then verify its failure paths and local TLB behavior independently of the controller.

CPU7B2 should then attempt only a bounded, fault-contained, read-only xAPIC snapshot on an explicitly qualified BSP lane. Keep the PIC/PIT authoritative and the APs offline. Defer x2APIC, selector-based I/O APIC inspection, duplicate EOI cleanup and route changes to their own qualification scope. Require explicit NMI lane evidence and keep MSI out of that lane until vector ownership is resolved.
