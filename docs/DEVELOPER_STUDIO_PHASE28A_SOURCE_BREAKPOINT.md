# Developer Studio Phase 28A — Source Breakpoints

Phase 28A extends the Phase 27Z NativeElf entry breakpoint with one
pre-launch, user-selected source breakpoint. The compiler emits the mapping;
the linker carries it into the final image; the NativeElf run service resolves
the requested project-relative path and line before it patches executable
memory.

## Prerequisite and scope

Phase 27Z supplies the asynchronous run owner, AMD64 vector-3 handling,
generation-bound debug identity, register snapshots, original-byte restore,
Resume, cancellation, and normal GUI cleanup. Phase 28A reuses that machinery.

This phase intentionally does not implement stepping, watches, locals,
expressions, call stacks, a breakpoint collection, dynamic breakpoint edits,
or a Developer Studio debugger pane. There is exactly one source selection in
the request and it is a one-shot breakpoint: Resume restores the original
instruction and does not reinsert `INT3`.

## Source-map architecture

The flow is:

```text
source statement
  -> AMD64 emitter statement boundary
  -> CompiledModule sourceMappings[]
  -> .gx.meta object record
  -> LinkedProgram finalCodeOffset
  -> GXSM trailer in the final ELF
  -> NativeElf source request and INT3 target
```

The compiler records a statement only when that statement emitted at least one
instruction. A record contains:

| Field | Meaning |
| --- | --- |
| `functionIndex` | Translation-unit function identity |
| `line`, `column` | 1-based source location; column is retained for future exact selection |
| `moduleCodeOffset` | First generated byte for the statement |
| `instructionBytes` | Generated byte range for the statement |

Mappings are sorted by module code offset before serialization. A requested
line resolves to the earliest matching executable range. A request with
column zero means “any column on this line”; a nonzero column requires an
exact match. Blank, comment-only, declaration-only, unknown, and past-end
locations fail instead of guessing at a nearby line.

## Object format and cache identity

The live object ABI was 8 at the start of this phase and is 9 now. The
`.gx.meta` header grew from 104 to 112 bytes. The append-only metadata fields
are:

```text
offset 88  sourceMapCount
offset 92  sourceMapMetadataBytes
offset 96  metaBytes
offset 100 objectBytes
offset 104 object checksum
```

Each object source-map record is a bounded 20-byte little-endian record. The
object writer validates count, order, function index, line/column, code range,
metadata byte count, and checksum. Reopen/deserialization performs the same
checks before restoring the records. A malformed or stale object is rejected
under the existing object-cache recovery path; no runtime breakpoint is
installed from malformed metadata.

The source file identity remains the existing canonical project-relative
translation-unit path. It is not duplicated in every record. The object also
retains the source byte count and FNV-1a source hash already used for cache
identity. Include/dependency metadata remains unchanged, so Phase 27V
dependency invalidation continues to control warm-object reuse.

## Linker and final ELF metadata

The linker keeps one bounded source-file table per ordered translation unit,
one deduplicated function-name table, and linked records containing:

```text
sourceFileIndex, functionIndex, line, column,
finalCodeOffset, instructionBytes
```

`finalCodeOffset` is computed during the real link from the module code base
offset plus `moduleCodeOffset`. The debugger never reconstructs this from a
disassembly or from a remembered address. The linker rejects out-of-range
records and missing function exports.

The bootstrap ELF writer appends a deterministic, non-loadable `GXSM` source
map trailer after the ELF file bytes. The trailer contains fixed-size source
paths, source byte counts/hashes, function names, linked records, a payload
size footer, and an FNV-1a checksum. It is included in the BuildResult hash
and file size, but it is outside every `PT_LOAD` range and cannot change code
permissions or runtime image layout. The final ELF validator continues to
validate the native executable using the ELF/`PT_LOAD` bytes only.

The resolver verifies the trailer magic/version/size/checksum, exact code
offset and code size, bounded source/function strings, every mapping range,
and the requested canonical project-relative path. It then returns:

```text
imageBase + codeFileOffset + finalCodeOffset
```

The NativeElf service separately validates that the address lies in the
validated runtime image and that the current project source still has the
recorded byte count and hash. This binds the mapping to the artifact, source
version, and debug generation.

## Request, trap, and paused snapshot

`gx_development_run_request` now appends `debugSourcePath`,
`debugSourceLine`, and `debugSourceColumn`. A source selection requires
debug-controlled execution, a nonempty safe-relative path, and a nonzero
line. Path traversal, absolute/device paths, malformed source identity,
unknown files, and unmapped lines are rejected before temporary App Model
registration becomes active.

With no source selection, the Phase 27Z entry-debug policy remains available.
With a source selection, the loader asks the run service for the resolved
target and installs the same page-permission-protected one-byte `INT3` patch
at that target. The persistent ELF is never modified.

On vector 3 the handler verifies the active generation, owner/context state,
target range, installed binding, and architectural `RIP == target + 1`. The
paused snapshot reports:

```text
pauseReason        = SourceBreakpoint
targetAddress      = normalized breakpoint address
instructionPointer = normalized address
rawTrapRip         = architectural post-INT3 RIP
context.rip        = normalized address
sourcePath         = src/main.cpp
sourceLine         = requested line
sourceColumn       = requested column (zero means wildcard selection)
functionName       = gx_main
```

While the target is stopped, the owner remains active and can poll the copied
snapshot. The run snapshot also reads the bounded live NativeElf host-log
buffer, which is necessary because the final `NativeElfRunReport` is normally
copied only after target teardown.

Resume restores the saved byte, clears the one-shot binding, normalizes RIP
back to the instruction start, and schedules the target. The original
instruction therefore executes exactly once. The selected breakpoint is not
reinserted after Resume.

## Phase 28A fixture and proof

The QEMU fixture is:

```text
scripts/fixtures/phase28a/guidexos.project
scripts/fixtures/phase28a/app/app.json
scripts/fixtures/phase28a/src/main.cpp
```

The selected location is `src/main.cpp:10` in `gx_main`, the assignment
`breakpointValue = breakpointValue + 1;`. The preceding `log()` statement
emits `DEVELOPER_STUDIO_PHASE28A_PRE_BREAKPOINT_ONCE`. The selected target is
inside the function body, before window creation and before the later GUI
operations. After Resume the fixture renders `28A GUI 28`, closes through the
normal compositor path, completes, and releases cleanly.

Focused proof command:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\smoke-compiler-bootstrap.ps1 `
    -Phase28AOnly -BootCount 1 -TimeoutSeconds 120
```

The smoke covers clean build, line-999 rejection, changed-source rejection,
source breakpoint install and real vector-3 hit, pre-breakpoint log, no GUI
before Resume, source/function/line/RIP snapshot identity, owner-side polling
while paused, Resume, GUI render, close, completion, release, cleanup, and
normal Run of the same source-map-bearing artifact without a debugger patch.

The observed positive evidence includes:

```text
target=0x0000000010001046
original=0x0000008B
raw_rip=0x0000000010001047
function=gx_main
sourcePath=src/main.cpp
sourceLine=10
normalized RIP=0x0000000010001046
```

The exact target is produced by the compiler/linker source map. It is not
hard-coded by the fixture or debugger. The pre-breakpoint log and absence of
any compositor window prove earlier user code ran while later GUI side effects
remained blocked. The resumed run renders `28A GUI 28` and reaches normal
close/teardown.

## Warm builds, relocation, and negative controls

The host object test proves deterministic serialization, object reopen,
linker/final-image resolution, unknown/non-executable line rejection, source
map trailer corruption rejection, two-file source identity, and rebuild
relocation. The relocation case inserts a supported local statement before the
selected log line and resolves the updated line to a different final code
offset; no old address is retained.

The QEMU source-edit control changes `src/main.cpp` after a successful build.
Preparation re-reads the current source identity and fails with
`ARTIFACT_CHANGED`; it does not register or patch a target. The line-999
control rejects an unmapped line as `ARTIFACT_INVALID`. Object checksum and
metadata validation reject corrupted objects before link.

Normal Run does not consult source-breakpoint fields and does not install an
`INT3`; the same final ELF renders and closes normally. A Debug request without
a source selection retains Phase 27Z entry-breakpoint behavior.

## Deferred work and limitations

The implementation supports one pre-launch, one-shot source breakpoint in
project-owned translation-unit source. It does not yet support dynamic
breakpoint collections, stepping, locals, watches, expressions, call stacks,
conditional/data breakpoints, inline/header-origin UI, DWARF/PDB/CodeView, or
remote attach. Header declarations remain dependency metadata rather than
interactive breakpoint locations. The standalone Developer Studio repository
was not modified to add debugger UI.
