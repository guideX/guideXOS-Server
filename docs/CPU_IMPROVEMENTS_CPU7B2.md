An exception during PIC dispatch or a nested exception can overwrite the live dispatch stack. Existing exception gates use IST0, including NMI and double fault. `CLI` leaves NMI delivery possible. Vector 17 (`#AC`) and vector 21 (`#CP` on supporting CPUs) supply an error code, but the stubs synthesize a zero. ## Implemented probe and fixup

`BSP_APIC_BASE_PROBE_DIAGNOSTIC=1` includes CPU7B1 admission and selects the new probe. The build rejects the combination with CPU6's pre-IDT `BSP_APIC_DIAGNOSTIC=1` reader. The CPU7B1-only flag still exercises the original admission-only path. The ordinary AMD64 build omits the probe and its call site. The diagnostic runs once from the UEFI framebuffer boot path after the kernel GDT/TSS and normal IDT are loaded and the PIC is remapped and masked, before PIT registration, ordinary STI, protected tasks or Native ELF launch. CPU1 must enumerate CPUID, long mode, MSR and APIC support. CPU3 must report logical processor 0 as the sole online BSP. The boot reader checks the loaded TSS selector and entry state, and takes a one-shot attempt inside an atomic ownership guard. [Kernel build](../kernel/Makefile) · [Boot call](../kernel/core/main.cpp) · [Probe eligibility](../kernel/arch/amd64/bsp_apic_base_probe.cpp) · [Interrupt initialization](../kernel/core/interrupts.cpp)

1. The assembly adapter accepts the expected kernel CS and SS, rejects TF/NT/VM and CR4.CET/FRED, saves the caller's IF via `pushfq`, and clears IF. It saves the live IDTR with `SIDT` and verifies its full limit and base against the expected kernel IDT before installing the detached copy. The copy has an assembly front end only at vector 13. Vector 2 (NMI) and vector 8 (double fault) use separate 4 KiB emergency IST stacks and an assembly-only halt loop during this window. NMI and double fault retain their normal gates outside the window. Other vectors retain their original entries. The original IDT is never edited. [Interrupt setup](../kernel/core/interrupts.cpp) · [Fixup assembly](../kernel/arch/amd64/bsp_apic_base_fixup.asm)
2. Immediately before the sole `RDMSR`, the adapter loads ECX with `0x1B` and arms the exact interrupted RSP. Vector 13 checks a nonzero armed RSP, ECX, the zero hardware error word, `CS=0x08`, `SS=0x10`, the saved stack pointer, permitted flags including IF clear, and the exact opcode RIP. A match changes only the saved RIP to the fixed failure continuation, restores its scratch registers and flags, discards the hardware error word and executes `iretq`. The 64-bit return frame restores RIP, CS, RFLAGS, RSP and SS. A mismatch tail-jumps to `exception_stub_13` with the original hardware frame, GPRs and entry flags. No C++ call, DF-dependent operation, XMM/x87 operation or general recovery table runs in the special entry. [Fixup assembly](../kernel/arch/amd64/bsp_apic_base_fixup.asm) · [Intel SDM, Vol. 3A, 64-bit mode stack and return](https://cdrdv2-public.intel.com/874240/325462-090-sdm-vol-1-2abcd-3abcd-4.pdf)
3. Success and the fixed failure continuation clear the armed RSP and restore the original IDTR before returning. EDX:EAX is written to the output on success only. The leaf uses volatile Microsoft x64 registers and restores its stack and IF on every return. The caller releases ownership on success and failure, and publishes no sample on rejection or fault. The contract is for the architectural `#GP(0)` from this opcode in the cold BSP lane. Other exception classes, including virtualization-specific interceptions, follow their own exception path. The qualified execution environment is the ordinary UEFI QAC guest described below. [Fixup assembly](../kernel/arch/amd64/bsp_apic_base_fixup.asm) · [Probe ownership](../kernel/arch/amd64/bsp_apic_base_probe.cpp)

The CPU7B1 evaluator consumes an observed value immediately, with no persistent cache or mapping plan. It decodes the hardware BSP bit, global enable, x2APIC enable and base using the CPU6 decoder. Admission then requires a supported xAPIC encoding, the CPU1/CPU3 initial APIC ID match, a valid physical width and page, the resolved CPU2/CPU5 MADT page, and agreement between the two sources. It also rejects a declared I/O APIC in that page. Normal PIC/PIT initialization resumes after the diagnostic. [Decoder](../kernel/arch/amd64/bsp_apic.cpp) · [Admission evaluator](../kernel/arch/amd64/bsp_xapic_admission.cpp)

## Remaining mapping prerequisites and next scope

CPU7B1 still requires an exclusive platform MMIO reservation with RAM and reserved-range exclusions, a reserved vacant virtual slot, and an alias audit covering identity/device windows, large pages and all applicable roots. It needs an audited active four-level CR3, supervisor/read-only/NX/non-global leaf evidence with observed EFER.NXE and CR0.WP, and a strong UC result for the complete page from the selected PAT entry and resolved MTRRs. The producer must establish platform address constraints, including applicable encryption or KeyID bits. Table frames must have an accountable owner and fit under CPU4's 1,024-page ceiling. A future publisher needs off-tree preparation, rollback, verification, invalidation and teardown before any register read. The existing VirtIO MMIO helper does not supply those contracts. [CPU7B1 ownership and transaction requirements](CPU_IMPROVEMENTS_CPU7B1.md#mapping-infrastructure-audit) · [Legacy MMIO](../kernel/core/mmio.cpp)

Scope CPU7B3 to independent ownership, effective cacheability, alias and permission evidence, plus a transactional single-page mapping plan and teardown with synthetic cases. Keep the first publication before any task CR3 exists. Qualify a hardware failure path only if an environment can naturally or verifiably deliver `#GP(0)` for the exact probe with an independent host deadline. Keep broader exception-entry corrections in a dedicated CPU7B2R1 if the work needs runtime fault handling. Controller-register reads, APIC routing, IPI/AP startup, and MSI/vector ownership changes need separate qualification.

## Cross-branch and ABI risks

CPU7B2 adds no BootInfo fields, version or checksums. It consumes the CPU branch's existing checked inventory and interrupt-topology extensions. Modern Input, Disk Manager, Security Settings and .NET Support differ in their handoff and entry contracts. Integrate matching loaders and kernels and revalidate those layouts, the kernel CS/SS, active IDT geometry, TSS IST ownership and cold boot call ordering before carrying the diagnostic across branches. The original `exception_stub_13` symbol and frame contract are integration dependencies. Native ELF still uses synchronous CPL0 entry and its existing ABI and recovery policy. The protected task still uses a separate RSP0/`0x80` path with IF clear.
