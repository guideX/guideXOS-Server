# C158 — Second Production Managed Application: Calculator

## Result

**Outcome A — the NativeAOT managed stack runs a second, distinct production application.** The managed Calculator launches through the ordinary App Model, handles bounded signed Int64 arithmetic from the pointer and keyboard, surfaces arithmetic errors without escaping into the host, and closes with its controls and input owners released. Notes still launches before and after Calculator in the same production boot.

Evidence is recorded in `out/dotnet/c158-managed-calculator-final-20261002-v2/c158-proof-manifest.json` and `c158-ordinary-restoration-manifest.json`. The evidence directory is generated by `scripts/dotnet/run-c158-managed-calculator.ps1`; it is build output and is not committed.

## Existing Calculator audit and identity

The repository already has a native built-in Calculator under the identity `gxos.builtin.calculator`. No managed Calculator identity existed. C158 adds `com.guidexos.apps.managed.calculator`, selector `6`, and the distinct display/launch name **Managed Calculator**. The original native record and launch identity remain registered. Both managed applications use the existing composite image, while the App Model resolves the canonical managed app ID to selector 6.

The fixed managed catalog grows from two descriptors (Workspace and Notes) to three. The desktop pinned Start entries grow from 15 to 16 and All Programs entries from 18 to 19. These are bounded additions; no registry or menu becomes dynamically sized. The production launch path is Start Menu → canonical app ID → built-in metadata → existing NativeAOT composite launch → selector-6 factory → Calculator surface.

## Controls and layout

The Calculator is an independent application class with its own controller, arithmetic core, lifecycle, and tests. It has no Notes document/session dependency. It owns one read-only Label display and 18 Buttons. Controls are application-owned; a flat `GuideXosControlHost` registers them and handles focus/input routing without owning their lifetime.

The client surface is 292 × 270 pixels. The display is at `(20, 38)`. Buttons use explicit geometry: four 64 × 28 columns at x positions 12, 80, 148, and 216, with rows starting at y=66 and a 36-pixel row step. The final Equals button spans 200 pixels. The 18 controls are `C`, `Bsp`, `+/-`, `/`, digits 7–9, `*`, digits 4–6, `-`, digits 1–3, `+`, `0`, and `=`. No Grid, recursive layout, or ownership tree was added.

The host’s fixed maximum was increased from 10 to 20, still bounded. Its default remains 8; Calculator explicitly creates a capacity-18 host and registers exactly 18 controls. Existing smaller hosts retain their capacities. Launch, close, and relaunch checks confirm 18 registrations on launch and zero after teardown.

## Arithmetic and display behavior

The arithmetic core’s packed primitive payload is **21 bytes**: signed left operand, unsigned entry magnitude, pending operator, phase, digit length, sign, and error. The unsigned magnitude permits the Int64 minimum value to be entered without taking an unrepresentable positive signed value. The controller also owns one fixed 18-element button-reference array and a fixed-capacity control host; there is no expression tree, history, or per-command control creation.

The state machine is `EnteringLeft`, `OperatorPending`, `EnteringRight`, `ShowingResult`, and `Error`. Input is signed Int64 only, formatted as base-10 ASCII with an optional minus sign, no grouping, locale, or exponent. Entry is capped at 19 digits and checked against the positive or negative Int64 magnitude before committing each digit. Overflow displays `Overflow`; arithmetic never wraps silently.

- Addition and subtraction use boundary checks before the signed operation.
- Multiplication guards the `Int64.MinValue × -1` cases and checks the product against the divisor to detect overflow.
- Division truncates toward zero (`7 / 2 = 3`, `-7 / 2 = -3`). Division by zero displays `Divide by zero`; `Int64.MinValue / -1` displays `Overflow`.
- Toggling the sign of `Int64.MinValue` enters `Overflow`. Zero remains canonical `0`, without negative zero.
- `C` and Escape clear to display `0`, no pending operator/error, empty entry, and `EnteringLeft`.
- Backspace edits only the active numeric entry (`123 → 12 → 1 → 0`) and is a no-op while showing a result or in Error.
- A second operator before right-side digits replaces the pending operator. Chained operations evaluate immediately from left to right (`2 + 3 * 4 = 20`); there is no precedence parser.
- Equals evaluates the pending operation; Equals without one and repeated Equals retain the current value. Equals immediately after an operator evaluates with zero as the right operand.
- A digit after a result or error begins a fresh value. An operator after a result uses that result as the next left operand. An operator in Error is ignored until Clear or a new digit.

## Pointer, keyboard, and focus

Pointer and keyboard route through the same command methods (`InputDigit`, `ChooseOperator`, `ToggleSign`, `Backspace`, `Clear`, and `Evaluate`). Production pointer input exercised `12 + 34 = 46`, Clear, and `6 * 7 = 42`; focused routing also activates Backspace by pointer. Production keyboard input exercised `7 * 8 Enter = 56`, Escape, `9 / 2 Enter = 4`, subtraction, Backspace, sign toggling, Tab, and Shift+Tab.

Keyboard digits use the managed KeyChar path. `+`, `-`, `*`, `/`, and `=` use decoded characters, so shifted `+` and `*` follow existing Shift transport. Enter evaluates unless a focused Button activation takes priority; Enter’s paired CR/LF KeyChar is consumed to prevent duplicate evaluation. Space activates the focused Button through existing host semantics. Escape clears, and Backspace edits the active entry. Calculator defines no Control shortcuts and consumes Ctrl chords without turning them into arithmetic input.

Registration order gives cyclic Tab traversal in visual order: `C`, `Bsp`, `+/-`, `/`, `7`, `8`, `9`, `*`, `4`, `5`, `6`, `-`, `1`, `2`, `3`, `+`, `0`, `=`. Equals is the initial focus target; focused Button Enter/Space uses the existing Button route, exactly once.

## Lifecycle and shared application state

Calculator follows the one-active-managed-surface model. A Notes → Calculator → Notes transition through Start Menu created and destroyed the corresponding surfaces in order. Notes also launched successfully before this transition. Calculator close dispatches through the existing Host ABI action path; the ABI was not changed. Each close unregisters all Calculator controls, clears the active app instance, and leaves modal owner, popup capture, and drag owner empty. Relaunch creates a fresh Calculator at zero; arithmetic state is not persisted.

The focused lifecycle suite passed 25 fresh launch/use/close cycles. Production boot 3 additionally recorded 27 Calculator launches and 26 closes, leaving only the final active instance. Calculator’s suite snapshots `GuideXosClipboard.Shared` and confirms the bytes and length are unchanged through test, launch, and teardown. It adds no clipboard commands or Notes-specific state.
