# NativeAOT PAL/runtime replacement

Status: 2026-07-23. The exact Workstation `gcenv` replacement remains PASS.
The separate NativeAOT Windows PAL/runtime family is inventoried and the
MSVC-compatible C boundary is compiled, but an active four-object archive
replacement is not yet authorized. HostLog is independently fixed by the
existing guideXOS runtime-pack FLS/reverse-P/Invoke binding. `RhInitialize`
was not called.

## 1. Objective

Remove mandatory Windows platform dependencies from the NativeAOT PAL/runtime
surface while preserving the locked MSVC AMD64 object ABI. The bounded target
is `PalRedhawkCommon.cpp.obj`, `PalRedhawkMinWin.cpp.obj`, `thread.cpp.obj`,
and `time.c.obj`; this work is separate from the completed
`gcenv.windows.cpp.obj` replacement.

## 5. Replacement strategy

Strategy B was selected for the analysis: replace only source/object units
whose platform calls can be isolated and prove startup reachability before
publishing an archive. The current evidence does not permit a partial active
archive because MinWin and `thread.cpp.obj` contain shared PAL state and
optional imports in the same object. Strategy A would leave duplicate or
inconsistent state if only the 19 names were rebound. Strategy C remains the
fallback if source-level separation is required.

The builder therefore stops after exact extraction, provenance, import
inventory, and ABI-contract compilation. It does not mutate the NuGet cache
or claim symbol parity for an adapted PAL archive.

## 6. Narrow ABI boundary

[`guidexos_nativeaot_pal_contract.h`](../../tools/dotnet/runtime-pack/src/platform/guidexos_nativeaot_pal_contract.h)
defines a C-compatible, versioned, pointer-width-explicit callback table.
It specifies:

- MSVC AMD64 / Win64 calling convention;
- `uint32_t`, `uint64_t`, `uintptr_t`, and `int32_t` widths;
- process-scoped callback ownership, with no generic C++ object crossing;
- opaque VM and future event/handle ownership;
- callback return values as explicit success/failure integers;
- explicit thread identity, stack bounds, counter, frequency, sleep, yield,
  and FLS callbacks;
- fail-closed behavior when hooks are absent or the ABI version/size is wrong.

The implementation is
[`guidexos_nativeaot_pal_contract.cpp`](../../tools/dotnet/runtime-pack/src/platform/guidexos_nativeaot_pal_contract.cpp).

## 7. FLS implementation

The existing guideXOS FLS manager already proves dynamic index allocation,
per-thread values, initial and worker contexts, detach callbacks, release,
generation-safe reuse, and index-zero compatibility. The new contract maps
those operations through C callbacks. It has not yet been bound into the
stock MinWin `PalInit`/attach/detach object, so exact PAL FLS parity remains
OPEN rather than being inferred from the inactive adapter proof.

## 8. Thread implementation

The required future path is current native-thread identity, stack-bound
reporting, ThreadStore attach/detach, yield/sleep, and thread exit. Existing
generic native-thread and ThreadStore/FLS probes pass, including a plain
worker lifecycle. The real finalizer/helper thread was not started. Binding
the locked `Thread`/`ThreadStore` ABI to those facilities is still pending.

## 9. Timing implementation

The contract requires a real monotonic counter and a nonzero frequency from
the same source, plus sleep and yield callbacks. The source mapping is
`minipal_hires_ticks`, `minipal_hires_tick_frequency`, and
`minipal_microdelay`. The counter frequency must describe the guideXOS clock;
no fabricated Windows QPC frequency is allowed. The exact PAL object has not
yet been rebuilt, so no timing PASS is claimed for the stock object.

## 10. Resolver/module behavior

The MinWin object also contains module and resolver functions. Static/current
image resolution can be supported only when the exact image is known. General
`LoadLibrary` behavior, fabricated handles, and unsupported dynamic loading
are not implemented. Resolver reachability is a separate gate and is not
hidden by the 19-candidate inventory.

## 11. Fail-fast behavior

Fatal paths must remain non-returning and preserve the reason. The contract
returns errors only for adapter calls whose source contract returns an error;
it does not turn fail-fast into success. MinWin fail-fast, hijack, and context
paths remain outside this bounded replacement until their exact thread-state
and ABI contracts are proven.

## 12. Archive reconstruction

[`build-guidexos-nativeaot-pal.ps1`](../../tools/dotnet/runtime-pack/build-guidexos-nativeaot-pal.ps1)
validates the lock hash, source commit/blob identity, extracts the four exact
members, captures dumpbin symbols/imports/headers/directives, compiles the
MSVC contract object, and emits JSON manifests. It leaves package-cache files
untouched. It intentionally emits `activeArchive: null` until source/object
replacement and exact symbol parity are complete.

## 13. Symbol parity

The 53/53 parity result applies to the completed Workstation `gcenv` object,
not this PAL family. The new contract exports only its own C boundary symbols;
it does not pretend to define `PalInit`, `ThreadStore`, or the PAL C++ ABI.

## 14. Remaining imports

The 19 records are in
`out/dotnet/nativeaot-pal-runtime-replacement/imports/inventory.json`.
The raw object symbol dumps remain alongside the provenance manifest. The
mandatory startup-facing records are FLS, VM, current-thread identity,
counter/frequency, sleep/yield, and stack bounds. Event/handle, resolver,
process capability, hijack, and background-thread imports remain later or
conditional until proven otherwise.

## 15. Hosted exact-symbol probe

No exact stock PAL entry point was called in this pass. The current hosted
managed proof uses the separate bounded guideXOS runtime-pack platform object;
it is not evidence that the four stock PAL objects have been replaced. The
contract object compiles with the locked MSVC ABI, but a hosted exact PAL
probe is therefore `BLOCKED`, not PASS.

## 16. QEMU ABI bridge

No unsafe direct call from MSVC COFF/Win64 C++ into MinGW ELF/SysV C++ was
added. The selected design is a future PE/COFF Win64 probe with only exported
C-compatible contract functions, loaded through the existing fixed-base
pipeline. A SysV-to-Win64 assembly trampoline is acceptable only for those
narrow exports; it is not a bridge for generic C++ objects.

## 17. QEMU exact-symbol probe

The exact PAL QEMU probe was not run because no active PAL replacement archive
exists yet. Existing generic native-thread, stack, ThreadStore, FLS, VM,
event, mutex, and true-VM QEMU proofs remain PASS. The exact Workstation GC
QEMU probe remains blocked by the known ABI boundary.
