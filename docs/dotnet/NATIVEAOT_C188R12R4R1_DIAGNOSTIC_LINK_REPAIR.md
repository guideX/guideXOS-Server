## Link failure and dependency boundary

The retained C188R12R4 failure is in `out/dotnet/c188r12r4-factory-attribution/nativeaot-candidate-003/`. Its `nativeaot/obj/release_win-x64/native/link.rsp` passes the generated `HostLogProof.obj` to the final link and excludes `kernel32.lib`. `nativeaot/artifacts/build-native-hostlog.log` records four `LNK2001` errors attributed to that object: `FreeLibrary`, `GetProcAddress`, `LoadLibraryExW`, and `SetThreadErrorMode`. No ELF was produced in that attempt.

`HostLogProof.obj` is generated by NativeAOT/ILCompiler from `samples/managed/HostLogProof/HostLogProof.dll`; it is not a checked-in or directly compiled object. The `HostLogProof.ilc.rsp` response file names it as an ILC output. The new reachable imports came from the R4 guest probes in `GuideXos/C188R12R4FactoryDiagnostics.cs`, which declare three `[DllImport("__Internal")]` functions. In the Windows `win-x64` NativeAOT translation, `__Internal` went through CoreLib's default P/Invoke resolver (`DefaultAssemblyLoadContext` / `InteropHelpers.ResolvePInvokeSlow` and its `GetProcAddressWithSuffix` path). Those resolver dependencies pulled Windows loader calls into `HostLogProof.obj` even though the probe targets were statically linked native guest functions.

The earlier R12R3 diagnostic NativeAOT link did not have these unresolved imports. The resolver implementation existed in CoreLib, but the R4 `__Internal` P/Invokes made it reachable. The proof-disabled production profile does not define the R4 factory-attribution feature and does not include these calls. The R4 build properties that select the feature are `HostLogProofC188R12R4FactoryAttribution=true` and `PublishAot=true`; production omits the attribution property. The production NativeAOT and ELF link profile likewise excludes the guest-only binding.

The first incorrect boundary was treating static guest-native calls as ordinary dynamic P/Invokes during Windows-targeted NativeAOT translation. `HostLogProof.obj` is where the references land, not the component that owns the Windows loader behavior. That behavior is not needed by the guest instrumentation.

## Repair and host/guest contracts

`HostLogProof.csproj` now adds `DirectPInvoke Include="__Internal"` only when R4 attribution is enabled for NativeAOT and the focused hosted test build is not selected. The generated `HostLogProof.ilc.rsp` includes `--directpinvoke:__Internal`; the final link response still excludes `kernel32.lib`. The three native C ABI probe functions are called directly and appear as static symbols in the map. Their old `__pinvoke_...` fixup-cell declarations and runtime initialization writes were removed from the R4-only platform initialization path. No Windows API stubs, unresolved-symbol suppressions, allocator changes, or linker workarounds were added.

The Windows-hosted test configuration continues to use the managed capture backend. Its test-only capture is bounded to 64 lines, and the existing Windows runtime loader behavior was not altered. The focused hosted factory tests still build and pass without selecting `__Internal`.

The guest factory logger writes through the existing host serial route using a 192-byte stack buffer and bounded `GuideXosText` appends. The native allocator trace writes with `persistentSerialPutString` and fixed-width `persistentSerialPutHex64`; its formatter does not call a managed allocator. The hosted regression checks the fixed-format line's calculated maximum of 242 bytes.

The allocator behavior is unchanged. For arrays, an invalid context or fast-capacity miss emits `C188R12R4_ALLOC` evidence before the existing fail-fast call. For objects, a fast-capacity miss is recorded before the existing `RhpNewFast` slow-path fallback; a later `allocation-result` is recorded if that call returns. These records do not make an absent return successful. No diagnostic is added after a fatal transition, and the 64 KiB arena is unchanged. Allocation failure evidence is therefore available for the supported array fail-fast and object fallback boundaries; behavior after an unobserved fatal transition remains subject to the guest trace.
