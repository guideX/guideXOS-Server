# NativeAOT workstation GC C78: earliest region-supply origin and lifecycle coverage

## Result

C78 is a bounded Level 1 coverage-repair phase with Outcome H: the C77 descriptor-birth model is corrected by the locked-source audit, which shows that NativeAOT USE_REGIONS reserves one large range and uses preallocated `seg_mapping_table` metadata slots. The final proof image reuses the accepted C67/C76/C77 records. It does not ship a second live C78 ledger because the first live-ledger implementation changed the address-sensitive ONE/SIX controls.

The accepted controls remain valid and deterministic:

| Control | Input | C76/C77 final basic | Confirmation boots | Peak C77 events |
| --- | --- | ---: | ---: | ---: |
| ONE | `15mid8`, retained=15, object=`0x10E80`, tail=320 | 1 / 1 | 3 | `0xDA` |
| SIX | `baseline16`, retained=16, object=`0x10018`, tail=216 | 6 / 6 | 3 | `0xD0` |

All six confirmation boots report zero event overflow, invariant failures, sensitive diagnostic allocations, fail-fast events, and page faults. Ordinary kernel/ESP restoration and proof-artifact cleanup passed on every run.

## Why the live C78 ledger was not retained

The first implementation added a separate fixed C78 event/snapshot state (`0x400` events and `0x300` snapshots) and hot-path callbacks for reserve, range allocation/release, descriptor materialization, list transfer, contexts, expansion, and snapshots. Its records were bounded and source-accounting-only, but the extra NativeAOT image footprint perturbed the sensitive controls: development probes produced non-accepted ONE results such as `4/4`, including with snapshots and hot-path callbacks disabled. The accepted C77 control remained `1/1` when built through the same harness.

That evidence is retained under `out/dotnet/c011ec78-region-supply-origin-coverage/development/`. The final C78 mode therefore reuses the already accepted C67/C76/C77 fixed records and keeps the extra source genealogy as an offline audit. This preserves the requested no-managed-workload-change and no-production-mutation properties while making the limitation explicit.

## Locked-source genealogy correction

The audit is against `out/dotnet/c68-locked-nativeaot-runtime-2/src/coreclr/gc/`:

- Heap initialization and the earliest range boundary are `gc_heap::initialize_gc` (around line 14120), `global_region_allocator.init` (around line 14257), and `allocate_initial_regions` (around line 14068/14262).
- `make_card_table` establishes the `seg_mapping_table`; `get_region_info_for_address` and `get_region_info` return metadata slots for addresses.
- Region supply and materialization flow through `region_allocator::allocate_region`, `gc_heap::make_heap_segment`, `gc_heap::init_heap_segment`, `gc_heap::get_new_region`, and `gc_heap::allocate_new_region`.
- The relevant production collections are the generation segment chains and `free_regions[basic_free_region]`, `free_regions[large_free_region]`, and `free_regions[huge_free_region]`.
- Expansion is reached through `a_fit_segment_end_p`, `uoh_a_fit_segment_end_p`, `grow_heap_segment`, and `expand_heap`.
- Free-range retirement/coalescing is represented by `delete_region_impl`, `move_highest_free_regions`, `find_first_valid_region`, `thread_final_regions`, and the allocator free-block logic documented in `gcpriv.h`.
- Context ownership is represented by `init_alloc_info` and `fix_allocation_context`.
- No production split function was found; the locked source retains a SOH split TODO. C77's zero split/coalesce/context markers remain “not observed,” not proof of absence.

The key model change is that “descriptor creation” is not equivalent to allocating a new region object. A range can be reserved once, represented by preallocated metadata, and later reused or reinterpreted through the region mapping. That is why C77's first observed create/commit event cannot be treated as the region's earliest origin.

## Limitation and next milestone

C78 does not yet trace every final SIX basic region backward through a live pre-workload descriptor/range ledger. The next smallest milestone is an offline or post-build census that reuses existing C67 storage, or runs outside the address-sensitive ONE/SIX image, and proves the first five-region genealogy edge without adding a second large NativeAOT runtime state.
