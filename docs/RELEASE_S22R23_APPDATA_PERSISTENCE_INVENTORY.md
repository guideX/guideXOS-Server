## Selected persistence boundary

The smallest useful existing workflow is the kernel Modern Settings Personalization page: an explicit wallpaper/gradient Apply plus system-icon visibility Apply. Both already pass through the desktop owner, have real effects, and have save/readback/error statuses. S22R23 will give these selected values a dedicated `/AppData` store, load them after the data volume is mounted, and leave other root configuration and document paths alone.

The storage file will use a FAT-compatible 8.3 name and an explicit format/version. Missing state will leave the trusted-image/default values in effect. Invalid or incompatible state will be ignored with a diagnostic and will not trigger data-volume formatting or cleanup. No file on `/AppData` will be considered an executable or package source.

## Owner decisions carried forward

Model B is the Public Technical Preview target; OpenSSH SSHSIG over a signed manifest remains planned, not approved as a final release contract. The system environment is disposable/rebuildable. Persistent documents, user files, and supported application settings/data are required. Unqualified hardware is not arbitrarily blocked; real security and destructive-storage safeguards remain. Single-monitor resolution controls are deferred and multiple monitors are deferred to v0.3.1 or v0.4. Production signing-key creation/custody, publisher verification-key distribution, an official publication channel, final release contract, and public-release authorization remain unapproved.

The high-priority Native ELF unresponsive-application requirement is handed to a dedicated architectural phase. Cooperative shutdown, CPU-bound infinite loops, preemptive scheduling, forced termination, cleanup, and memory-corruption isolation remain distinct concerns; the current PacMan-only integrity policy is not process isolation.
