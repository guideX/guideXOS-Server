## CPU1 changes

- Added an AMD64 capability API with an injectable CPUID reader and a native implementation for GCC/Clang and MSVC. The decoder uses fixed-size results and checks maximum-leaf bounds before reading optional leaves. It reports the vendor, the complete brand string when available, basic and extended maxima, and the individual physical and maximum linear address widths. Zero widths represent unavailable values. [Public API](../kernel/arch/amd64/include/arch/cpu_capabilities.h) · [Implementation](../kernel/arch/amd64/cpu_capabilities.cpp)
- Feature fields distinguish `Unreported`, `Clear`, and `Set`. They cover APIC/x2APIC, TSC and timing-related flags, MSR, SSE2, XSAVE/OSXSAVE, AVX/AVX2, PCID, SMEP/SMAP, NX, 1 GiB pages, long mode, and the hypervisor bit. OSXSAVE represents the sampled OS state advertised by CPUID. AVX and AVX2 fields represent their independent CPUID bits. XCR0 policy, extended-state layout, and feature activation are outside this API. [Intel SDM, Vol. 2](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html) · [AMD CPUID Specification](https://www.amd.com/content/dam/amd/en/documents/archived-tech-docs/design-guides/25481.pdf)
- Topology reports valid subleaf 0 from `0x1F`, then `0x0B`, then a leaf-1 initial APIC ID when leaf 1 advertises APIC. The legacy count field also requires HTT. The source, level type, shift, and count hint describe the sampled CPU's CPUID output. Firmware enumeration and successful CPU bring-up are required to establish an online processor inventory. [Topology decoder](../kernel/arch/amd64/cpu_capabilities.cpp#L78) · [Intel CPUID topology reference](https://www.intel.com/content/dam/develop/external/us/en/documents/architecture-instruction-set-extensions-programming-reference-806695.pdf)
- The protected address-space platform and gated MMIO path now share the narrow CPUID NX query. They retain their existing EFER.NXE checks, writes, and diagnostics. The full capability snapshot is callable but has no boot or UI caller. The AMD64 Makefile source glob picks it up and both Visual Studio project lists include it. The x86 and non-x86 dispatch paths retain their existing providers. [Task NX policy](../kernel/core/amd64_memory_foundation.cpp#L129) · [MMIO NX policy](../kernel/core/mmio.cpp#L94) · [Architecture source selection](../kernel/Makefile#L123)

## Remaining risks and integration points

| Workstream | Dependency or risk |
| --- | --- |
| CPU reporting and Settings | The snapshot samples one execution context, possibly with hypervisor-masked leaves. CPU affinity is required for a coherent per-CPU snapshot once migration is available. Topology coverage stops at the first standard subleaf and legacy fallback. Vendor-specific topology, online counts, calibrated CPU frequencies, and per-CPU utilization remain future work. Address widths are processor maxima and can differ from the current page-table mode. |
| Protected task and scheduling | AP startup would require owned per-CPU GDT/TSS and entry/exception stacks, GS state, AP-safe frame allocation, and a cross-CPU TLB policy. The current checked invalidation model is single-CPU and rejects active PCID. Async scheduling also needs full interrupt-frame and x87/SSE/XSAVE ownership plus a fault return/reaper contract. The S22R28 diagnostic needs separate guest qualification before it can supply evidence for those changes. [Memory platform](../kernel/core/amd64_memory_foundation.cpp#L140) · [Frame-owner synchronization contract](../kernel/core/include/kernel/physical_frame_owner.h#L92) · [S22R28 limits](RELEASE_S22R28_PROTECTED_TASK_EXIT_AND_FAULT_HANDLING.md#fault-policy) |
| Input and desktop | PS/2 keyboard and mouse delivery depend on IRQ1/12, the PIC, and the IRQ-to-desktop path. The desktop also relies on IRQ0 for wakeups and services input, display updates, and audio on the existing loop. Controller changes need end-to-end keyboard, pointer, timer wakeup, and desktop responsiveness qualification. ## CPU2 priorities

1. Build a read-only discovery path from `BootInfo::AcpiRsdp`. Define a bounded physical table reader with explicit mapping and lifetime rules. Validate RSDP and RSDT/XSDT signatures, sizes, checksums, and address ranges before reading MADT entries. Return local APIC and x2APIC IDs, ACPI processor UIDs, and firmware enablement/online-capable flags, with explicit duplicate and malformed-entry handling. Test absent and corrupt tables, truncation, duplicate IDs, disabled entries, and wide x2APIC IDs using hosted fixtures. [UEFI Forum ACPI Specification, §5.2](https://uefi.org/specs/ACPI/6.6/05_ACPI_Software_Programming_Model.html)
2. Add a bounded boot-CPU diagnostic that correlates CPUID with the validated firmware inventory and gives distinct statuses for firmware-advertised and actually online processors. When authorized in CPU2, qualify that diagnostic on separately identified guest media and verify the legacy timer, keyboard, mouse, and ordinary desktop path together.
3. Stage controller/routing qualification, AP startup and per-CPU ownership, clock calibration, and preemption as separate milestones with their own acceptance gates. Resolve the protected-task and driver dependencies before any of those paths can be made default.

**Recommendation:** Make CPU2 a read-only ACPI/MADT processor inventory with a boot-CPU cross-check and keep PIC/PIT operation as the qualification baseline.
