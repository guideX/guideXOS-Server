## Active AMD64 interrupt architecture

| Area | Implementation and implications |
| --- | --- |
| Entry and controller | The AMD64 entry clears IF. Core interrupt setup installs GDT/TSS, remaps the master and slave 8259 to vectors `0x20–0x2F`, masks all IRQs, installs and loads the IDT, then enables local maskable interrupts. Each IRQ registration publishes one handler and unmasks its line and, for a slave line, master cascade IRQ2. The stubs pass the legacy IRQ number to the dispatcher. It invokes the handler and sends non-specific EOI to the slave for IRQ8–15, then to the master. This path has no controller ownership abstraction, shared INTx handler list, or IRQ7/15 ISR-based spurious handling. The current global stack and recovery context require explicit treatment of IRQ, fault, and NMI nesting before any wider delivery. The assembly entry contract includes Microsoft x64 stack alignment, shadow space, register preservation and `iretq`. ## Read-only discovery

The stock loader records topology during CPU2's existing traversal on the first successful final UEFI memory-map fetch. It reads the RSDP, selected RSDT or XSDT, and checksummed MADT through the same bounded physical views. Root and MADT limits remain 256 entries and 64 KiB. The parser reads controller addresses as integers from the ACPI table. It makes no additional physical-view requests, UEFI allocations, mappings, port accesses, or controller accesses.

| MADT data | Captured fields and checks |
| --- | --- |
| Header and type 5 | Raw 32-bit LAPIC base and MADT flags including `PCAT_COMPAT`. Retains up to four type-5 64-bit addresses and offsets. The header supplies the candidate when there is no override and its address is nonzero and 4 KiB aligned. Exactly one valid override supersedes it. A short supported record, an invalid override, or multiple overrides makes the candidate unresolved. Duplicate and contradictory override values are recorded on both retained entries. |
| Type 1, I/O APIC | Retains up to 16 IDs, 32-bit MMIO addresses, 32-bit GSI bases, and offsets. Checks the reserved byte, nonzero address, natural register alignment, and representability of the selector/data window. Equal records are duplicates. Reused IDs, overlapping register windows, reused GSI bases, and a window that overlaps the effective LAPIC page are flagged. Distinct GSI bases alone cannot establish disjoint operational ranges. |
| Type 2, Interrupt Source Override | Retains up to 24 bus/source/GSI tuples, raw flags, and offsets. Checks ISA bus 0, source IRQ 0–15, and reserved flag bits. For either two-bit mode, `00` means bus-conforming and resolves to high or edge for ISA, `01` explicitly selects high or edge, `10` is reserved, and `11` explicitly selects low or level. Equal source and GSI with equivalent valid mode are duplicates, including explicit/default ISA equivalents. Different targets or modes for the same source are conflicts. Different sources explicitly targeting the same GSI receive a shared-GSI marker. The full unsigned 32-bit GSI is retained. |
| Type 0 and type 9 | CPU2 continues to report the Local APIC or x2APIC ID, ACPI UID, flags, validity, duplicates and conflicts. CPU3's BSP correlation and offline descriptor rules retain the existing processor contract. |
| Other record types | The checked length advances the walk. Uninterpreted records are counted, with a separate count for types 3, 4 and 10, which describe NMI sources or LINT assignments. CPU5 supplies no NMI route or PCI routing plan. |

A record with a valid outer boundary and a short type 1, 2 or 5 payload increments the malformed count and retains the first such offset. Processor inventory remains usable in that case. A broken outer record boundary, short CPU2 processor record, ambiguous root, or failed table validation suppresses the topology handoff. Larger supported records use the known prefix. Total structurally decodable records are counted through the end of the MADT even if a retention limit is reached. Conflict flags describe retained pairs, so a truncated topology cannot establish consistency. [ACPI MADT §5.2.12](https://uefi.org/specs/ACPI/6.6/05_ACPI_Software_Programming_Model.html#multiple-apic-description-table-madt) · [Parser and bounds](../guideXOSBootLoader/acpi_processor_inventory.cpp) · [Record layout and flag decoding](../guideXOSBootLoader/acpi_processor_inventory.h)

The v3 base stays at 572 bytes. CPU2's v1 processor extension still occupies 2,640 bytes from offset 576 and keeps bit 4 and its checksum. CPU5 uses an independently checksummed 744-byte tail at offset 3,216 in the same 4 KiB BootInfo page. It uses signature `INTR`, version 1 and a fixed size, with no new BootInfo flag. The kernel accepts this tail only after validating the containing UEFI BootInfo page and processor extension and confirming a structurally valid MADT status. A CPU2–CPU4 loader leaves the tail zero, so a CPU5 kernel can consume the earlier processor inventory and report topology unavailable. Earlier kernels can still consume the CPU2 prefix from the CPU5 loader. Hosted fixtures exercise the optional tail and rejection. [BootInfo base](../guideXOSBootLoader/guidexOSBootInfo.h) · [Checked extensions](../guideXOSBootLoader/bootinfo_acpi.h)

`CPU_INVENTORY_DIAGNOSTIC=1` enables the one-shot `[CPU5]` serial report alongside `[CPU2]` and `[CPU3]`. It prints raw and resolved firmware fields, record issues, and the BSP's separate CPUID APIC, x2APIC, TSC-deadline, and physical address width values. The BSP width can flag a reported address that exceeds it. The default kernel emits none of these reports. A MADT address, a CPUID bit, and a current controller mode represent three different observations. CPU5 records the first two and logs controller registers as uninspected. CPU5 adds no startup or online transition for a secondary, and the IRQ, timer, task arena, public ABI, and Native ELF paths continue through the CPU4 entry points. ## APIC compatibility and activation prerequisites

1. **Local APIC state.** Establish vendor-supported mode and register access from CPUID MSR/APIC support and a separately gated BSP read of `IA32_APIC_BASE`. Compare the hardware base and mode with the firmware address and the BSP ID. Access to an xAPIC MMIO window requires a verified supervisor, NX, UC mapping and a cache-type alias audit. The current dynamic MMIO implementation is gated for the AMD64 VirtIO GPU probe. Its presence gives no stock APIC mapping contract. x2APIC uses mode-specific MSRs and requires a supported, explicitly chosen transition policy. Reserve vectors for spurious and error delivery, decide LINT and NMI handling, mask unused LVT sources, and establish known EOI and priority behavior before enabling or routing delivery. Preserve the qualified boot table and task mapping contracts. [AMD64 Architecture Programmer's Manual, Vol. 2](https://docs.amd.com/v/u/en-US/24593_3.44_APM_Vol2) · [Intel SDM, Vol. 3](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html) · [Existing kernel MMIO path](../kernel/core/mmio.cpp)
2. **I/O APIC coverage and destination.** Reconcile each hardware ID and version with its firmware record. Reading the version and max redirection index uses a serialized selector write followed by a data-window read, so that probe requires its own mapping, controller ownership and register-access contract. Verify the full register window, prevent cache-type aliases and validate `GSI base + max index` without overflow. Reject overlap, missing coverage for required lines and unresolvable duplicates. Allocate vectors separately from IRQs and GSIs. Resolve polarity, trigger and destination width before writing masked redirection entries. x2APIC processor IDs can exceed the narrow destination field used by conventional I/O APIC and current MSI encoding. Establish a reachable BSP target or qualify an interrupt-remapping design. [ACPI I/O APIC and GSI definitions](https://uefi.org/specs/ACPI/6.6/05_ACPI_Software_Programming_Model.html) · [Intel I/O APIC datasheet](https://pdos.csail.mit.edu/6.1810/2017/readings/ia32/ioapic.pdf) · [Intel SDM](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)
3. **8259 transition and timer.** Treat `PCAT_COMPAT` as firmware's declaration of a dual 8259. Establish whether firmware uses a virtual-wire or platform-specific legacy path. Define who masks the PIC and IOAPIC lines, drains or handles pending interrupts and acknowledges each delivery. APIC mode on a PC-AT-compatible system requires the 8259 lines masked. Test a single active route per source, device acknowledgment before controller EOI where required, level-triggered reassertion and spurious interrupts. Keep the PIT as a measured reference. Qualify continuity of IRQ0, IRQ1, IRQ3 and IRQ12 and one timekeeper before adding a second timer source. TSC or deadline features alone provide no calibration, idle wakeup, or cross-CPU monotonicity evidence. [ACPI MADT flags and overrides](https://uefi.org/specs/ACPI/6.6/05_ACPI_Software_Programming_Model.html) · [Current PIT and PIC](../kernel/core/pit.cpp)
4. **Per-CPU entry.** Allocate separate kernel stacks, TSS descriptors, RSP0 and IST stacks. Each executing CPU needs its own GDTR, IDTR and TR setup, stable current-CPU lookup across privilege transitions, and per-CPU IF, nesting and exception state. An immutable IDT image may be shared once each CPU can load it independently. Test normal IRQs, nested fault/NMI and double-fault isolation, CPL3 entry/exit, frame integrity and the Microsoft x64 call boundary. Keep current-task and fault-recovery storage CPU-local before permitting parallel execution of those paths. [CPU3 ownership audit](CPU_IMPROVEMENTS_CPU3.md#single-cpu-assumptions) · [Live interrupt assembly](../kernel/core/interrupts.cpp)
5. **IPIs.** Reserve purpose-specific vectors, define delivery and EOI ownership, validate explicit destinations and CPU state, and bound delivery and response acknowledgments. Define release/acquire publication, exclusion and timeouts before using an IPI for rendezvous or remote TLB invalidation. Verify expected, unsupported, and unresponsive destination behavior with one known target before any broadcast policy. [Intel SDM APIC and multiprocessor initialization](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)
6. **Secondary startup and synchronization.** Reserve and map a low-memory startup trampoline and per-AP bootstrap stacks with distinct ownership. Validate full APIC IDs and a bounded INIT/SIPI handshake with feature sampling on each AP, mode/CR3 setup and per-CPU entry state installed before making it visible as online. Define failed-AP quarantine and keep a timed-out startup's resources owned until execution can be excluded. Before an AP can enter ordinary kernel paths, establish synchronization for the allocator, frame owner, page tables, MMIO configuration, serial, timer and input state, IRQ registration, devices, and shared runtime. Publish translations and require remote invalidation acknowledgment before reclaiming frames. Local IRQ masking alone cannot serialize shared state between CPUs. Scheduling, SIMD/XSAVE ownership and timer preemption require independent qualification. [CPU3 synchronization audit](CPU_IMPROVEMENTS_CPU3.md#synchronization-readiness) · [AMD64 system programming reference](https://docs.amd.com/v/u/en-US/24593_3.44_APM_Vol2)

## Cross-branch integration

- **Modern Input `843ab3f8`.** Its expanded BootInfo v4 assigns bits 3–4 to ACPI remapping scan and table presence and additional bits to IVRS/DMAR copies. CPU4/CPU5 use bits 3–4 for task frames and ACPI processor inventory. Agree on a versioned flag registry and a single extension placement and bounds contract before exchanging loader and kernel builds. Treat DMA remapping, IRQ remapping, xHCI transport, and legacy PS/2 delivery as distinct ownership contracts. Validate keyboard and pointer delivery on both device paths when routing changes.
- **Disk Manager `723046ff`.** Its v3 storage-profile mask also occupies bits 3–4. A shared base version alone cannot distinguish those contracts. Preserve polling during controller evaluation and audit each storage controller before enabling INTx/MSI, including source acknowledgment, request completion, DMA ordering and shared-vector behavior. NVMe's present command path polls completions. The stock QAC lane uses a RAM disk and provides no physical storage IRQ coverage. [NVMe command path](../kernel/core/nvme.cpp)
- **Protected tasks and Security Settings.** Keep the RSP0, IST, private/shared CR3 and off-stack reaping contracts when moving interrupt state. Reconcile Security Settings' timer-driven Native ELF pilot separately. It overlaps general interrupt return, active runtime and extended-state ownership. Include Input Reliability's QAC and input checks in future runs and keep AMD64 handoff code architecture-scoped when integrating shared entry or build changes. ## Recommended CPU6 scope

Keep a BSP-only controller characterization milestone. First qualify a hosted vector and route plan using the MADT fixtures and synthetic redirection counts, covering GSI overflow, gaps, overlaps, NMI/LINT ownership, invalid encodings, destination width, and loss of required legacy routes.
