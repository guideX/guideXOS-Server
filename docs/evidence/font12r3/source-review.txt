FONT12R3 source review (read-only)

SettingsWindowConstraints: kernel/core/kernel_apps.cpp:16769-16778 sets minimum 560x360, preferred 760x500, maximum 1180x820. Settings initialization at 16544-16556 copies preferred and minimum values into KernelWindow.
Window dimension semantics: kernel/core/kernel_compositor.cpp:865-896 draws the border and titlebar within window->w/window->h, then calls owner->draw(x, y+TITLEBAR_HEIGHT, w, h-TITLEBAR_HEIGHT). Thus the Settings constraint is the outer window rectangle; at minimum, the app draw callback receives width 560 and client height 336 (titlebar 24).
Clamping: registerWindow at kernel_compositor.cpp:241-255 enforces max(app minimum, generic 200x100). Pointer resize begins at 661-669 and is captured by window ID; handleMouseMove at 570-600 computes from drag-start geometry, clamps to those minima, updates w/h, and marks the same window dirty. The drag handler does not impose the Settings maximum values. Topology reconciliation separately clamps to the available work area and bounds its effective minimum by that work area; registration applies the minimum only.
Redraw: drawAllWindows/drawWindow at kernel_compositor.cpp:848-920 uses the current w/h, calls the app draw callback, draws widgets and resize grip, and clears dirty.
Native resize API: no requestWindowResize/setWindowSize implementation was found. kernel/core/include/kernel/kernel_ipc.h declares WindowResize, but no kernel consumer was found. The QEMU-only qemu_display_input_proof adapter creates its own QEMU Input Proof window and routes mapped events to the regular compositor; it does not address Settings or request a specific geometry.
Therefore the only live Settings resize route available to this run was pointer input. No production source or input-driver changes were made.
