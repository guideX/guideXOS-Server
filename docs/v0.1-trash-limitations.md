# guideXOS Server v0.1 Trash limitation

Non-empty folder Delete/Move to Trash is deliberately refused in v0.1.
Before any Trash directory, restore metadata, destination copy, or source
mutation is started, the VFS snapshots the folder's stable child entries. If
it finds an entry other than `.` or `..`, the operation returns
`VFS_ERR_DIRECTORY_NOT_EMPTY` and the Desktop reports:

`Unable to delete folder: folder is not empty`

Files and empty folders continue to use the existing verified copy/delete
Trash transaction. Recursive clipboard folder copy remains separately bounded
by depth and entry limits; it is not used by Delete until recursive Trash
rollback and failure-injection coverage is complete.
