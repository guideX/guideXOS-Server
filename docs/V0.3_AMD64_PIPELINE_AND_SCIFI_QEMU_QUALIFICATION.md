It also stages the ImageViewer smoke fixture from `assets\Images\BlueVelvet\16\image.png` as `/WALL/IVSMOKE.PNG` in the FAT32 image. The image is made from the staged wallpaper directory, not supplied by a guest-side post-boot copy.
2. `build.ps1` builds PacMan, invokes that generator with output `ESP\ramdisk.img`, builds the UEFI bootloader and AMD64 kernel, then stages their outputs under `ESP`.
3. `guideXOSBootLoader\main.cpp` opens `ramdisk.img` on the boot volume with `LoadFile`, allocates memory and reads it before handoff. It writes the address and size to `RamdiskBase` and `RamdiskSize` in boot info and sets the valid flag.
4. `kernel\core\main.cpp` consumes those boot-info fields and calls `desktop::set_wallpaper_image_pack`. `kernel\core\desktop.cpp` attaches the boot memory as a read-only FAT ramdisk. On a persistent-root boot it mounts the image at `/system`; wallpaper files resolve under `/system/wall`. On release-media boot without a persistent root it mounts at `/` and aliases `/system` to `/`, so the packaged paths still resolve as `/system/wall` and `/system/wall/ivsmoke.png`.
5. The checked-in `run-qemu.bat` command exposes `ESP` as `-drive file=fat:rw:ESP,format=raw`, from which the bootloader loads the ramdisk before kernel startup. A valid acceptance command must substitute the candidate directory for `ESP` at this argument, or boot the ISO whose embedded FAT image contains that same ramdisk. Host-side injection after guest startup cannot satisfy this boot-time path.

The canonical `scripts\create-release-iso.ps1` currently reads `ESP`, then creates `dist\guideXOS-Server-v<version>-amd64.iso`; its options do not provide an alternate ESP or output root. The normal `build.ps1` likewise targets the workspace `ESP`. Its `-Clean` switch recursively removes `ESP`, so it was not used. No production behavior change was made.

## Wallpaper and image-pack architecture

Production source establishes this path:

1. Wallpaper source art is under `assets\Backgrounds`.
2. `scripts\generate-wallpaper-pack.ps1` converts/stages wallpaper PNGs, thumbnails and GXI files into a FAT32 runtime image. It also stages `ivsmoke.png` from the existing `assets\Images\BlueVelvet\16\image.png` fixture.
3. `build.ps1` writes that image as `ESP\ramdisk.img`; the release ISO packager requires `EFI\BOOT\BOOTX64.EFI`, `kernel.elf` and `ramdisk.img`.
4. `run-qemu.bat` exposes the writable `ESP` FAT volume to QEMU. The bootloader loads the root `ramdisk.img` and passes its address/size in boot information.
5. `kernel\core\main.cpp` gives that boot-time memory range to `desktop::set_wallpaper_image_pack`. `kernel\core\desktop.cpp` attaches it read-only and mounts it at `/system` when a persistent root is mounted; wallpaper paths resolve under `/system/wall`.

The dedicated workspace's `ESP\ramdisk.img` is a 64 MiB FAT32 image. A read-only FAT directory inspection found `/WALL/IVSMOKE.PNG` (792 bytes), the shipped wallpaper PNG/GXI set, and the generated `/APPS/PACMAN` directory. The parallel `out\wallpaper-pack\wall` staging directory also contains the wallpaper assets. Wallpaper/image-pack support is part of the v0.3 release experience, including when Sci-Fi is selected; it is shared desktop content, not Sci-Fi-specific art.

## Root-cause classification

**ISOLATED ACCEPTANCE-FIXTURE LIMITATION**

The prior acceptance report said the wallpaper pack was not mounted and the isolated ESP lacked usable image content. The boot path explains that result: without `ramdisk.img` present where the bootloader can load it at boot, boot information has no RAM-disk base/size and the kernel reports the image pack missing. Adding a PNG to the host-backed ESP after boot cannot change the already-loaded boot-time image-pack memory or cause a new mount. Normal build/release staging includes `ramdisk.img`; the dedicated workspace's local ESP and pack prove the content exists in the normal staging layout. No Sci-Fi integration or v0.3 packaging defect was demonstrated. This classification uses the supplied prior observation plus source and dedicated-workspace artifact evidence; the prior isolated fixture itself was not opened or modified.
